# Pocket Mortys 加模组原理

对《口袋莫蒂》**Pocket Mortys V2.41.0**（`com.conspiracyrick.pocketmortys`，
社区私服版）的资源结构分析，以及「模组到底改在哪一层」的结论。

分析样本：

| 文件 | 说明 |
|---|---|
| `已修改安装包dp.apk` | 改过服务器地址的安装包，1,127,003,006 字节解压后 / 4,202 个条目 |
| `口蘑数据包(1).zip` | 客户端数据目录快照（`/sdcard/Android/data/<包名>/files/`），726 个文件 |

---

## 0. 结论速览

1. 游戏是 **Unity 2022.3.62f2 + IL2CPP**（不是 Mono，所以不能塞 DLL 了事）。
2. 资源分**四层**，其中**第二层（下载缓存）最好改**，因为它**不经过下载校验**，
   而且改完**不用重装 APK**。
3. 包里 **12,846 个 Sprite / 12,601 个 Texture2D / 310 个 AudioClip / 50 个 TextAsset**。
   其中 **TextAsset 全是 JSON**，是数值向模组的主战场：
   抽卡掉率、莫蒂属性、技能威力、道具、商店、竞技场奖励，全在里面。
4. 用 **UnityPy** 可以完整闭环：解包 → 改 → 回写 → 重新解包读回来是对的。
   已验证 `TextAsset`（文本）与 `Texture2D`（贴图）两类。
5. 同一逻辑包**在多个地方各有一份**（`text` 同时存在于 APK 的 Android、
   APK 的 .iOS、下载缓存三处）。**改错地方就完全不生效** —— 这是最容易踩的坑。

## 1. 引擎与版本

从 APK 里读出来的事实：

```
assets/bin/Data/boot.config        build-guid=b8a13acd1aa943bda2687183957f639c
lib/arm64-v8a/libil2cpp.so         IL2CPP，ARM64
assets/bin/Data/Managed/Metadata/global-metadata.dat   11,144,917 字节
资源包 magic                        UnityFS + "5.x.x" + "2022.3.62f2"
```

`UnityFS` 头里那串 `5.x.x` 是被人为抹掉的 Unity 版本号，真实版本看后面那段
`2022.3.62f2`。**这个版本号很关键**：社区流传的包是 `2022.3.62f1` 构建的，
两者不通用 —— 用错版本表现为**界面一个字都不显示**（字体图集对不上）。

## 2. 资源分四层

```
① APK 内置（StreamingAssets）
   assets/AssetBundles/Android/text.assetbundle      750,887 字节
   assets/AssetBundles/.iOS/text.assetbundle       1,045,497 字节
   ├─ 只有 text 一个包，是离线兜底的
   └─ 改它必须重打包 + 重签名 APK

② 下载缓存（设备数据目录）★ 最好改
   /sdcard/Android/data/<包名>/files/
       UnityCache/Shared/<包名>/<目录名>/__data     ← 包正文（UnityFS）
                                     /__info       ← 23 字节文本
   ├─ 155 个包都在这里，是运行时真正被加载的那份
   └─ 改它不用碰 APK，adb push 即可

③ 自建 CDN
   cdn/AssetBundles/<group>/Android/<包名>.assetbundle
   └─ 私服下发用，要同时对 manifest.json 里的 version 加一

④ 几个 .dat（BinaryFormatter 序列化，非资源包）
   files/AssetBundle.dat      31,826 字节  完整 157 条 manifest（含 crc/version/url）
   files/SegmentedWorld.dat    7,553 字节
   files/Settings.dat          3,620 字节
   files/Tournament.dat        1,627 字节
   files/promotions.dat        4,033 字节
   └─ 不是 AssetBundle，改它们要解析 .NET BinaryFormatter，性价比低
```

`UnityCache` 的目录名不是随机的，它是 **12 个零字节 + 小端 4 字节 version** 的 hex：

```
version 1004 → ec 03 00 00 → 000000000000000000000000ec030000
version  219 → db 00 00 00 → 000000000000000000000000db000000
```

**替换时必须保持目录名不变**，否则等于换了一个包，游戏会重新下载。

`__info` 的确切内容是（实测）：

```
Shared/__info     b'1792219309\n1\n1779259310\n'
<包名>/__info     b'-1\n1779259343\n1\n__data\n'
```

## 3. 资源包里到底有什么

把 155 个包全扫一遍，对象类型统计：

| 类型 | 数量 | 可改性 |
|---|---:|---|
| `Sprite` | 12,846 | 只读（它只是「引用 + 裁切框」，像素在 Texture2D 里） |
| `Texture2D` | 12,601 | ★ **可换** |
| `Transform` | 477 | — |
| `GameObject` | 477 | — |
| `SpriteRenderer` | 315 | — |
| `AudioClip` | 310 | 只读（FSB 流式，见 §7） |
| `AssetBundle` | 155 | 包自身的元数据 |
| `MonoBehaviour` | 63 | 可改类型树（剧情数据，见 §4.4） |
| `TextAsset` | 50 | ★ **可改，且全是 JSON** |
| `Animator` / `AnimationClip` / `AnimatorController` | 32 / 30 / 30 | — |
| `Shader` / `Material` | 12 / 12 | — |
| `MonoScript` | 8 | — |
| `Cubemap` | 1 | — |

贴图格式以**未压缩**为主，替换时不需要重新编码（这点很省事）：

| 格式 | 尺寸 | 数量 |
|---|---|---:|
| `ARGB4444` | 125×162 | 7,259 |
| `ARGB4444` | 126×162 | 2,193 |
| `ARGB4444` | 90×90 | 753 |
| `RGBA32` | 125×162 | 168 |
| `RGBA64` | 125×162 | 36 |

`125×162` 就是莫蒂立绘的格子尺寸 —— 想换角色形象，换这些。

### 4.4 `text` —— 本地化（11 种语言）

`DE` 546KB、`ES` 519KB、`FR` 525KB、`IT` 521KB、`PT_BR` 509KB、`EN` 491KB、
`RU` 494KB、`KO` 354KB、`JP` 351KB、`ZH_CN` 305KB、`ZH_TW` 304KB。

结构：

```json
{
  "TextDefs": { "PLAYER_NAME": {"label": "瑞克"}, ... },
  "SignPost": {...}, "Interactions": {...}, "PlayerAvatar": {...}, "Morty": {...}
}
```

### 4.5 剧情（`ep8xx`）

`ep802` ~ `ep810` 这几个包里有 63 个 `MonoBehaviour` —— 是剧情/演出数据，
可以用「类型树（typetree）」方式读出来改，但结构复杂，改错了容易崩。

## 5. 改法：UnityPy 闭环（已验证）

```python
import io, UnityPy
env = UnityPy.load(io.BytesIO(raw))          # raw = __data 的字节
for obj in env.objects:
    if obj.type.name == "TextAsset":
        d = obj.read()
        if d.m_Name == "GachaDefault":
            d.m_Script = new_json        # m_Script 是 str
            d.save()
data = env.file.save(packer="original")      # 回写
```

实测结果：把 `GachaDefault.drop_rates` 从 `[80,12,6,2]` 改成 `[100,0,0,0]`，
回写后重新 `UnityPy.load` 读出来就是 `[100,0,0,0]`。

贴图同理：

```python
d = obj.read()                # Texture2D
d.image = PIL.Image.open("新图.png")   # 尺寸须与 m_Width×m_Height 一致
d.save()
```

实测：把 `anime101` 里一张 709×708 的贴图换成纯色，回写后重新读，
像素值正确。

## 6. 三个坑（都已在工具里处理）

### 坑一：同一逻辑包有多个副本，改错地方不生效

`text` 有三份：APK 的 `Android`、APK 的 `.iOS`、下载缓存。它们的**内容还不一样**
（750KB / 1045KB / 2.7MB，是三个不同构建）。把 Android 的字节塞进 `.iOS` 槽位
会直接毁掉那个包。

> 工具的做法：让你显式选「编辑哪一份」；打 APK 时，被编辑那份直接回写，
> **其它副本按资源身份（type + name）重放同样的改动**，而不是复制字节。

### 坑二：manifest 里的 crc 对不上，而且不影响替换

`AssetBundle.dat` 里存着完整 manifest，每个包都有 `crc`。但实测：

| 包 | manifest crc | 实际 `zlib.crc32` |
|---|---:|---:|
| `appdata` | 1,847,994,213 | 70,722,838 |
| `text` | 1,661,817,716 | 2,678,693,821 |
| `mpdata` | 4,099,569,620 | 1,189,488,618 |
| `spdata` | 56,704,220 | 2,499,900,570 |

换了四种 CRC 变体（zlib / BZIP2 / MPEG-2 / Castagnoli）都对不上 —— 说明
manifest 的 crc 是针对**另一套构建**算的，和本地产物不是一回事。

**结论**：改下载缓存里的 `__data` 不经过下载校验，所以 **crc 不用管**。
（这也是本项目走缓存路线的原因之一：走 CDN 下发时 crc 校验是否会拦，
本机无法验证，缓存路线绕开了整个问题。）

### 坑三：大于 20 万字符的文本表

`ZH_CN` 30 万字符、`MortyAttacksInfo` 59 万字符。做预览功能时很容易顺手写
「只读前 20 万字符」，然后这个截断值一路传到导出和打包 —— **资源就被改坏了**。

> 工具的做法：`preview_text()` 默认**不截断**，只有界面显示才传 `limit`。
> `tools/selftest.py` 里有一条专门的回归测试盯着这个。

## 7. 三种落地方式

| 方式 | 改哪 | 设备上要做什么 | 适合 |
|---|---|---|---|
| **UnityCache** ★ | 下载缓存 | `adb push` 到数据目录 | 日常迭代，**不用重装** |
| **APK 重打包** | `assets/AssetBundles/` | 卸载重装 | 只有 `text` 在里面；做整包分发 |
| **CDN** | 私服目录 | 重启服务器 | 私服下发 |

### UnityCache 路线（推荐）

```bash
BASE=/sdcard/Android/data/com.conspiracyrick.pocketmortys/files
adb root
adb push UnityCache "$BASE/"
adb shell "chown -R 10289:10289 $BASE"
adb shell "chmod -R 777 $BASE"
```

工具会直接生成 `push.sh` 和 `推送说明.md`，照抄即可。

### APK 路线

APK 重打包有三个硬性要求，缺一条就装不上：

1. `resources.arsc` 必须**不压缩**且 **4 字节对齐**（targetSdk ≥ 30 的硬校验）。
   所以不能整包重压，只能「读原包、只换指定条目、其余连压缩方式原样拷贝」。
2. `zipalign` 必须在签名**之前**做。
3. 必须 v2/v3 方案签名（`apksigner`），只做 v1 的 `jarsigner` 装不上；
   旧签名的 `META-INF/*.SF|RSA|DSA|MF` 要先删掉。

实测：150.8 MB 的 APK，替换 1 个条目 → 对齐 → 签名，**16.6 秒**完成，
`apksigner verify` 通过（`V3.0 Signer: CN=PMNet, ...`）。

## 8. 做不到 / 没做的

| 想做的事 | 情况 |
|---|---|
| **换音频** | `AudioClip` 的采样不在对象里，`m_Resource` 指向包内 FSB 流式数据。换它要重编码成 FSB 并重建偏移，是另一个工程。**本工具只支持导出成 wav。** |
| **直接换 Sprite** | Sprite 只是引用 + 裁切框，得改它引用的 Texture2D 图集。工具会提示你去改哪张。 |
| **图集（atlas）重排** | 换整张图集是可以的（就是换 Texture2D），但改布局（增删精灵）不行。 |
| **加新角色** | 要动 `MortyInfo`（新增条目）+ 贴图 + `BundleAssetAssignment`，理论可行但没验证。 |
| **改 IL2CPP 逻辑** | 要走 `libil2cpp.so` 二进制补丁，属于另一个话题（前期工程里有工具）。 |

### 8.1 但「改不了」的范围比想象中小得多

一开始只做了 `TextAsset` 和 `Texture2D`，后来把覆盖面扩到了**包里每一个对象**。
实测结论：

| 类型 | 处理方式 | 回环验证 |
|---|---|---|
| `TextAsset` 及全部子类 | 文本，编辑 JSON | ✓ |
| `Texture2D` | 图片，换 PNG | ✓ |
| `Cubemap` | 图片，换 PNG（六面打成一张十字图） | ✓ 像素正确 |
| `Material` | 类型树 JSON | ✓ 改完重新解包一致 |
| `AnimationClip` | 类型树 JSON | ✓ 一致 |
| `Shader` | 类型树 JSON（`m_Script` 是空的，编译过的 shader 没有源码） | ✓ 一致 |
| `GameObject` / `Transform` / `SpriteRenderer` / `Animator` / `AnimatorController` | 类型树 JSON | ✓ 一致 |
| `MonoBehaviour` | 类型树 JSON | ✓ 一致 |
| `Sprite` | 只读（`Sprite.image` 能拿到裁切后的图，导出没问题，但换它没意义） | 导出 ✓ |
| `AudioClip` | 只读，导出 wav | 导出 ✓ |
| `AssetBundle` | 是包自身的元数据，不去动它，但能导出原始字节 | 导出 ✓ |

UnityPy 的 `read_typetree()` / `save_typetree()` 对这些类型都是通的，
所以「类型树」这条路实际上是**通用兜底**：任何对象都能导成 JSON、
改完塞回去。代价是 JSON 结构复杂、改错容易弄坏资源，所以界面上标成高级用法。

## 9. 怎么验证改对了

本工具在这台机器上**没法真的跑安卓游戏**，所以做了两层验证：

**第一层（工具自测，已全绿）**
```bash
.venv/bin/python tools/selftest.py --apk dp.apk --data 口蘑数据包.zip
```
覆盖：解包 → 改数据表 → 改贴图 → 重新解包校验改动生效 → 出 UnityCache 产物
→ 打 `.pmmod` → 打到干净会话 → 导出导入回环 → 大文本不截断。

**第二层（上机验证，需要你来做）**

1. 推上去之后启动游戏。
2. 看私服日志有没有 `GET /Aliases/rat/Android` 和 `AssetBundles/...` 请求。
3. 改 `GachaDefault.drop_rates` 为 `[100,0,0,0]` 是最直观的验证：
   抽卡应该次次出同一档。
4. 改 `text` 的 `ZH_CN` 里 `PLAYER_NAME`，启动后看名字变没变。
   **如果没变，说明游戏读的是另一份副本** —— 回到工具里换「编辑哪一份」再试。

> 一句话：格式层面已经验证到底，**运行时生效与否取决于你有没有改对那一份副本**。

## 10. 附：新增条目（加莫蒂 / 道具）

「改现有条目」和「加新条目」是两件事。加新条目难在**一张表不够**。

以莫蒂为例，同一个逻辑数据在 `spdata` 和 `mpdata` 里**格式完全不同**：

| 位置 | 结构 | 关键差异 |
|---|---|---|
| `spdata/MortyInfo` | 顶层键 = id 的 **dict** | 字段全是**字符串**，技能塞在一串 `"AttackA:1, AttackB:6"` 里 |
| `mpdata/MortyInfo` | **list** | 字段**有类型**（`number` 是 int），键名叫 `morty_id`/`asset_id` |
| `mpdata/MortyAttacksInfo` | list | `attacks` 是 `[{attack_id, level}]` |

外加 `appdata/BundleAssetAssignment`（形象资源登记）和 `text/<11 语言>`
（本地化）。所以加一只莫蒂要动 **5 处**，少一处就有一处出问题 ——
只改 spdata 则联机看不到，不改本地化则名字空白。

工具的做法是**克隆一条现有条目**再改：字段天然齐全、类型天然正确。
细节见 [新增条目说明.md](新增条目说明.md)。

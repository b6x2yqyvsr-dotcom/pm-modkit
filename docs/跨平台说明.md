# 跨平台说明

这个工具有**两个界面**，跑在不同的地方：

| 界面 | 用什么技术 | 跑在哪 |
|---|---|---|
| **桌面图形界面** | Dear ImGui（`imgui-bundle`） | Windows / Linux / macOS |
| **网页界面** | 自带的小 HTTP 服务 + 浏览器 | **所有平台**，包括 Android / iOS |

核心库 `modkit` 只依赖 Python 标准库 + Pillow + UnityPy，三平台通吃。

---

## 一、先说清楚：哪些能跑，哪些不能

| 平台 | 桌面图形界面 | 网页界面 | 命令行 | 说明 |
|---|:---:|:---:|:---:|---|
| **Windows x64 / arm64** | ✅ | ✅ | ✅ | `imgui-bundle` 有 `win_amd64`/`win_arm64` 轮子 |
| **Linux x86_64** | ✅ | ✅ | ✅ | `manylinux` / `musllinux` 轮子都有 |
| **Linux aarch64**（树莓派等） | ✅ | ✅ | ✅ | 同上，aarch64 轮子也有 |
| **macOS Apple Silicon** | ✅ | ✅ | ✅ | 只有 `arm64` 轮子 |
| **macOS Intel** | ⚠️ | ✅ | ✅ | `imgui-bundle` 没给 x86_64 轮子，得自己编译；网页版照常 |
| **Android（Termux）** | ❌ | ✅ | ✅ | 见下文，**这是手机上的正路** |
| **Android（原生 App）** | ❌ | — | — | 需要 NDK 重写，本工具不做 |
| **iOS** | ❌ | ✅ | ⚠️ | iOS 不给装 CPython 扩展；用浏览器连别的机器 |

> **为什么 Android / iOS 装不了桌面界面？**
> `imgui-bundle` 在 PyPI 上只有这些轮子：
> `win_amd64` `win_arm64` `manylinux_2_28_{x86_64,aarch64}`
> `musllinux_1_2_{x86_64,aarch64}` `macosx_14_0_arm64` `pyemscripten_wasm32`。
> Android 用的是 bionic libc，不是 glibc 也不是 musl，**装不上**；
> iOS 更彻底 —— 根本不允许运行这种带原生扩展的 Python 程序。
>
> 所以手机端走**浏览器**：核心逻辑跑在能跑的地方，界面用网页。

## 二、桌面版（Windows / Linux / macOS）

### 最快的方式：venv + 启动脚本

```bash
# Linux / macOS
cd pm-modkit
sh setup.sh
./启动.sh          # 图形界面
./启动网页版.sh     # 网页界面
```

```bat
:: Windows
cd pm-modkit
setup.bat          :: 双击即可
启动.bat            :: 图形界面
启动网页版.bat       :: 网页界面
```

`setup` 会在项目里建一个自带的 `.venv`，不动系统 Python。

### 不打脚本，手动来

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip
.venv/bin/python app/main.py                   # 图形界面
.venv/bin/python web/server.py                 # 网页界面
```

### 打成免安装程序

```bash
.venv/bin/pip install pyinstaller
python3 build/build_app.py            # 产物在 dist/口蘑Mod工坊/
python3 build/build_app.py --onefile  # 单个文件
```

产物：

| 平台 | 位置 |
|---|---|
| Windows | `dist/口蘑Mod工坊/口蘑Mod工坊.exe` |
| Linux | `dist/口蘑Mod工坊/口蘑Mod工坊` |
| macOS | `dist/口蘑Mod工坊.app` |

打好的程序也支持 `--web`：

```bash
./口蘑Mod工坊 --web --port 8765
```

> ⚠️ **PyInstaller 不能交叉编译**。要给 Windows 打包就得在 Windows 上跑。
> 三个平台的自动打包见 [`.github/workflows/build.yml`](打包与安装.md)，
> 推个 tag 或者手动触发就会各跑一台机器，产物传到 Actions 的 Artifacts 里。

## 三、手机端

### Android：Termux 里直接跑（推荐）

Termux 是个终端模拟器，能装真正的 Python。装完**在手机上就能改游戏**，
不用连电脑。

```bash
# 1. 装 Termux（从 F-Droid 装，别用 Play 商店那个老版本）
#    https://f-droid.org/packages/com.termux/

# 2. 在 Termux 里
pkg install -y git
git clone <本项目地址> pm-modkit && cd pm-modkit
bash android/termux-install.sh

# 3. 之后每次启动
bash android/termux-run.sh
```

然后手机浏览器打开 **http://127.0.0.1:8765**，就是完整界面。

安装脚本会自动：
- 用 Termux 仓库里的**预编译包**（`python-pillow`、`python-lz4`、`python-brotli`），
  比 pip 现场编译快得多
- 申请存储权限（`termux-setup-storage`），这样能读 `/sdcard` 上的 apk 和数据包
- 装不上的 C 扩展自动降级（见下）

> **关于装不上的那几个包**
> UnityPy 会依赖 `texture2ddecoder` / `etcpak` / `astc-encoder-py` / `fmod_toolkit`。
> 实测它们**只在处理压缩纹理（ASTC/ETC）和音频编码时才用到**，
> `import UnityPy` 本身不受影响。而这个游戏的贴图是
> **ARGB4444 / RGBA32 未压缩格式**，音频只导出不导入 ——
> 所以这几个装不上**不影响本工具的主要功能**。脚本会明确告诉你缺了什么。

**APK 重打包在手机上基本用不了**（要 apksigner/zipalign/JDK）。
手机上用网页版的「UnityCache」路线即可，那条路不需要这些。

### iOS：用浏览器连

iOS 没法装 Termux，也没法装 CPython 扩展。可行的用法：

1. 在**电脑**（或树莓派、NAS 等任何能跑 Python 的机器）上执行
   `./启动网页版.sh`
2. 让 iPhone 和那台机器连**同一个 Wi-Fi**
3. iPhone 用 **Safari** 打开终端里打印的那个地址，例如
   `http://192.168.1.23:8765`

界面会自动适配手机屏幕（底部标签栏）。用 Safari 的「添加到主屏幕」
还能当个 App 图标用。

### 电脑跑服务、手机当界面

这也是最省事的用法，**Windows 用户尤其推荐**：

```bat
启动网页版.bat
```

它会自动打开浏览器，并在控制台打印手机能用的地址。手机连同一个 Wi-Fi
打开那个 `http://192.168.x.x:8765` 就行。

## 四、APK 重打包的工具链

只有「**把改好的包打回 APK 并签名**」这个功能需要外部工具。
改包 + 出 UnityCache 产物**不需要任何外部工具**。

需要三样：`apksigner`、`zipalign`（都在 Android SDK 的 build-tools 里）、
`keytool`（JDK 自带）。

| 平台 | 装法 |
|---|---|
| **Windows** | 装 [Android Studio](https://developer.android.com/studio)（自带 SDK），或只装 [command-line tools](https://developer.android.com/studio#command-tools) 后 `sdkmanager "build-tools;34.0.0"`；JDK 装 [Adoptium](https://adoptium.net/) |
| **macOS** | `brew install --cask android-commandlinetools` + `sdkmanager "build-tools;34.0.0"`；JDK：`brew install openjdk` |
| **Debian/Ubuntu** | `sudo apt install android-sdk-build-tools default-jdk` |
| **Arch** | `sudo pacman -S android-sdk-build-tools jdk-openjdk` |
| **Termux** | `pkg install openjdk-17`（apksigner 要另想办法，基本不现实） |

工具会自动按这个顺序找，不用手动配：

1. 环境变量 `ANDROID_SDK_ROOT` / `ANDROID_HOME` / `ANDROID_SDK`
2. 各平台常见安装位置（Windows 的 `%LOCALAPPDATA%\Android\Sdk`、
   Linux 的 `/usr/lib/android-sdk`、macOS 的 `~/Library/Android/sdk` 等）
3. `PATH`
4. Termux 的 `$PREFIX/bin`

找没找到随时可以查：

```bash
.venv/bin/python tools/cli.py doctor      # Windows: .venv\Scripts\python tools\cli.py doctor
```

签名用的 keystore 会按这个顺序找，找不到就**现场生成一把**放在
`~/.pm-modkit/modkit.keystore`：

1. 环境变量 `PM_MODKIT_KEYSTORE`
2. `~/.pm-modkit/modkit.keystore`
3. 项目目录下的 `modkit.keystore`

> 换了签名，手机上要先**卸载旧版**才能装。

## 五、输出目录放哪

默认输出到「桌面/PM-Mod-输出」，桌面上没有就退到家目录下的同名目录
（Termux、无头服务器就是这种情况）。

想指定就各处都能填：

- 图形界面：「导出…」窗口里
- 网页界面：「导出」页里的输入框
- 命令行：`-o 目录`
- 环境变量：`PM_MODKIT_WORK`（网页版的工作目录，默认 `~/.pm-modkit`）

## 六、常见问题

**Q：Windows 上双击 `启动.bat` 闪一下就没了？**
先双击 `setup.bat` 装环境。还不行就用 `cmd` 手动跑 `启动.bat` 看报错，
或者跑 `.venv\Scripts\python app\main.py`。

**Q：Linux 上启动图形界面报「没有图形环境」？**
`启动.sh` 会检查 `DISPLAY`。服务器、SSH、WSL 无图形的情况下请用
`./启动网页版.sh`，然后从别的机器用浏览器连。

**Q：WSL 里怎么用？**
WSL2 支持 WSLg 的话图形界面能直接开；否则用网页版，
Windows 侧浏览器访问 `http://localhost:8765` 即可（WSL2 会自动转发端口）。

**Q：macOS 提示「无法打开，因为它来自身份不明的开发者」？**
右键点图标 →「打开」→ 再点「打开」。或者
`xattr -dr com.apple.quarantine dist/口蘑Mod工坊.app`。

**Q：手机上网页界面很卡？**
图片预览是按需缩略的，但一个包可能有上万个对象。用「搜名字」把范围缩小，
别在一个大包里翻到底。

**Q：手机浏览器打不开 `http://127.0.0.1:8765`？**
`127.0.0.1` 指的是「本机」。如果服务跑在电脑上，手机要用**电脑的局域网 IP**
（启动网页版时控制台会打印），并且两个设备在同一个 Wi-Fi。

**Q：网页版会把我改的东西传到网上吗？**
不会。它是个本地/局域网的小服务，没有外连，也没有任何云服务。核心代码里
唯一会访问网络的地方是……没有。
